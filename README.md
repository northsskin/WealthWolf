# Wealthwolf

A Duolingo-style personal finance course. Short lessons with real documents (pay stubs, bills, bank statements), a Wolf who checks your work, spaced repetition, XP and ranks. Built with React + Vite. Accounts and saved progress use Supabase.

The app lives in [`wealthwolf/`](wealthwolf).

## Run it

You need Node 20.19 or newer.

```bash
cd wealthwolf
npm install
npm run dev
```

Open http://localhost:5190. The port is fixed, because Google sign-in only allows that address.

`npm run dev:unlocked` does the same with every lesson unlocked and no account needed, for testing content.

`npm run check` checks every lesson file and lists any problems. Run it after changing content.

`npm run build` makes a production build in `wealthwolf/dist/`.

## Accounts (Supabase)

- `wealthwolf/.env` points at the shared Supabase project. Its two values are public by design. Never commit a secret or `service_role` key; personal overrides go in `.env.local`, which git ignores.
- Progress is saved in one table, `public.progress`, one row per player, with row-level security so players only see their own row. The SQL is in [`wealthwolf/supabase/migrations/`](wealthwolf/supabase/migrations). Add a new migration file for any database change.
- Sign-in methods: Google, and email with password. Lesson one works without an account; after that, players must sign up.
- **Google sign-in is in "testing" mode.** Only Gmail addresses listed under Google Cloud → Google Auth Platform → Audience → Test users can sign in. Add your partner there.
- For dashboard access, invite each other to the Supabase organization (Organization settings → Team).

## How the course is built

```
wealthwolf/src/data/
  sections.json               the sections, in order, with each section's final trial
  everyday-money/01-….json    one file per unit: its words and lessons
  earning/01-….json
  …
```

- Each unit file holds its glossary words (`terms`) and its lessons. Each lesson is a list of steps: multiple choice, true/false, number, fill the gap, order, match, sort, spot the problem on a document, and a budget builder. The full step format is documented at the top of [`src/lib/content.js`](wealthwolf/src/lib/content.js).
- In development, the app checks every unit when it starts and prints a `[content]` warning in the browser console for any problem. Problems include an unknown word, a word used before it's taught, or a broken answer.
- The unit files are generated by Python scripts in [`scripts/content-gen/`](wealthwolf/scripts/content-gen): `uNN_*.py` for Everyday Money, `eNN_*.py` for Earning, `cNN_*.py` for Credit & Debt. They share helpers from `lib.py`, which also check that every document's totals add up. To change a unit, edit its script and run it from that folder, for example `python3 e01_paycheck.py`. Editing the JSON by hand works too, but the next script run will overwrite it.
- Style rules for lessons:
  - Teach every new word inside the question where it first appears, using `[[word]]`.
  - Assume the learner knows nothing.
  - Mix lesson formats.
  - Use US rules, and label yearly figures with their year.

### Building the remaining sections

- [`docs/CONTENT_GUIDE.md`](docs/CONTENT_GUIDE.md) explains how a section is made and checked.
- [`docs/prompts/`](docs/prompts) has a ready-to-paste prompt for each of Sections 3–8, for Cursor or another AI agent.
- Build them in order (3, 4, 5, 6, 7, 8): later sections build on words taught in earlier ones.
- Use one branch and pull request per section. Every section adds itself to `sections.json`, so if two run at once, expect to merge that file.

## Design

Everything visual comes from the tokens in [`src/styles/tokens.css`](wealthwolf/src/styles/tokens.css): colours for light and dark mode, type scale, spacing, radii and motion. Use a token rather than a hard-coded value, and add a new token there if one is missing.
